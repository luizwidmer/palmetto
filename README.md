# Palmetto

<p align="center"><img src="assets/mascot.png" alt="Palmetto, the project mascot" width="220"></p>

**A clean-room compatibility runtime that runs a modern console build natively on Windows, built on your own PC from your own copy.**

Palmetto translates a retail console executable and its shaders into a native Windows program at build time: the
loader maps the console image, the runtime resolves its imports to open-source shims, the shader tooling translates the
console shaders to SPIR-V, and a Vulkan-backed D3D12 device executes the result.

> [!IMPORTANT]
> This repository contains **no game, no keys and no executable**, and it does not explain how to obtain them. You need
> your own legally acquired copy, with its files already readable on disk. Nothing here decrypts content or works around
> any protection measure. Everything a build creates — translated shaders, extracted assets, the runtime folder, your
> saves — comes from your own copy and stays on your PC. Never share those files.

## Build

Requirements: **your own copy** of the target console package, Windows 10/11 x64, ~400 GiB free for the full build,
Python 3.12+, .NET 8 SDK, Visual Studio 2022 with the C++ tools and Windows SDK 10.0.26100+,
[Vulkan SDK](https://vulkan.lunarg.com/) (`spirv-as`, `spirv-val`), LLVM 21+ with the **AMDGPU** target for
`llvm-mc` (the official Windows build has none; `tooling/scripts\build_llvm_mc.ps1` builds one), and `ffmpeg` on PATH.

```powershell
git clone https://github.com/luizwidmer/Palmetto
cd palmetto
python -I build_port.py --find                 # locate your own copy
python -I build_port.py --check                # verify it
python -I build_port.py --game "<pkg>" --out "<out>" --work "<work>" --stages shaders,runtime
```

`tooling/scripts\build_runtime.ps1` builds `palmetto.exe` on its own. Then:

```powershell
palmetto.exe --dry-run <pkg>\game.exe --game-dir <pkg>              # map the image, list imports
palmetto.exe --run     <pkg>\game.exe --game-dir <pkg> --overlay <dir> --trace-d3d12 --trace out.jsonl
```

For a comparable one-line summary of any attempt, use the harness:

```powershell
python -I tooling/boot_report.py --exe port\build\palmetto.exe `
    --image <pkg>\game.exe --game-dir <pkg> --overlay <dir> --timeout 150
```

## How it works

| Piece | What it does | Where |
|---|---|---|
| Shaders | carve DXBC, unpack native RDNA2, disassemble with LLVM `gfx1013`, translate to SPIR-V | `tooling/shader_carve.py`, `tooling/fssm_unpack.py`, `tooling/shader_disasm.py`, `tooling/rdna2spirv.py` |
| Runtime | maps the PE image, resolves imports to shims, console-ABI proxies over a Vulkan-backed D3D12 device | `port/` |
| Assets | validated resources inside the console's data archives, texture pools, audio banks | `tooling/arc9dump`, `tooling/ttpf_assets.py` |
| Progress | the README tracker below, generated from `docs/progress.json`; a fuller offline page of what passes and what blocks next | `tooling/readme_progress.py`, `tooling/progress_dashboard.py` |

Format and contract notes are indexed in [docs/README.md](docs/README.md).

## Rules

- **No game data, ever** — no archives, executable, carved files, shaders in any form, textures, models, audio, or
  logs and reports that quote them. Share outcomes (counts, pass/fail, error classes), not inputs.
- **No keys, decryption or protection workarounds.** The tools only read files that are already plain on disk.
- Short excerpts needed to explain a format (a few header bytes, one instruction) are fine in docs and comments.
